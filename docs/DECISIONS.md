# 架构决策记录（ADR，简版）

格式：编号 · 决策 · 理由 · 代价/后果。状态默认"已接受"，除非注明。

**ADR-001 · 程序证明溯源，模型只指出位置。** 模型输出 block_id + 逐字引文 + 值原文；偏移与定位由程序计算。
理由：小模型无法可靠输出坐标/页码，而子串检查是确定性的。代价：模型改写引文会被判为未通过，需要重试，并增加复核量。

**ADR-002 · 状态 `verified` 改为 `grounded`，并新增 `failed`/`derived`。** 理由：程序只能证明值有原文依据，不能证明值正确；基础设施失败与内容存疑必须分开统计。代价：与早期 Brief 用词不一致，需要同步（开放问题 1）。

**ADR-003 · "fuzzy 永不 grounded"写进契约校验器。** 理由：把关键安全性质从约定变成类型层面的保证。代价：契约层与校验逻辑轻度耦合。

**ADR-004 · doc_id = 内容哈希前缀；block_id 为文档内局部 ID；金标准使用原生位置。** 理由：ID 跨运行稳定，标注不随解析器升级失效。代价：同一文件重复输入会去重；解析器升级后历史结果中的 block_id 需要按引文重新锚定。

**ADR-005 · PDF 层拆为"后端字符流 + 自研版面 + 通用定位"，默认宽松许可证后端，PyMuPDF 仅为 AGPL 可选 extra（M1 不实现）。** 理由：仓库为 Apache-2.0 且要打包 exe；逐字几何让定位不再依赖 search_for 反查。代价：需要自研分行分段启发式（T4 难度高）；复杂版面能力弱于成熟库。

**ADR-006 · 归一化逐码点、偏移保持、只映射不删除标点。** 理由：可证明的回映射；避免 `12.5`≡`125` 类误匹配。代价：少数组合字符序列与整串 NFKC 结果不同（已在测试中固化）。

**ADR-007 · 值由程序规范化，双路径比较。** 模型给值原文，程序解析；同时在引文内识别提及；在规范化值上判等。理由：可导出性检查变成确定性检查，并覆盖大写金额、万元、中文日期。代价：类型系统需要逐类型维护解析器。

**ADR-008 · 跨块与错 ID 用确定性修复（相邻拼接、全文唯一重定位），之后才重试。** 理由：便宜、可审计、减少模型调用。代价：重定位依赖引文唯一，引文过短时会判为歧义。

**ADR-009 · 所有抽取层只产出 Candidate，并经过同一个 Verifier；Pipeline 从 M1 起就是生产者链。** 理由：M2 模板层、M3 决策层只是新的生产者，不需要改动 M1 契约。代价：M1 中有少量当前用不到的抽象。

**ADR-010 · 人工修正是追加写的覆盖层。** 理由：评测与复现不被人工编辑污染，复核过程可审计。代价：读取时需要合并覆盖层。

**ADR-011 · 复现依赖请求哈希缓存与 replay，而不是 seed。** 理由：GPU 与批处理的非确定性使 seed 无法保证逐字复现。代价：缓存含正文，必须放在被忽略的目录中。

**ADR-012 · 远端后端默认禁止。** 理由：把文档发往非本机服务属于数据出境，需要用户显式开启。代价：多一步配置。

**ADR-013 · 合成金标准来自 Writer 自身的记账，而不是被测解析器。** 理由：避免循环论证，否则解析器缺陷会被"自证"为正确。代价：PDF 需要自行排版并记录逐字坐标（T5b）。

**ADR-014 · 合成集与真实指针集分开报告；难度只在真实开发集上校准。** 理由：防止合成数据的分布让评测失真、防止在测试集上调参。代价：真实集规模小，置信区间宽。

**ADR-015 · 表格渲染默认逐格带表头（cell_lines），行式渲染作为消融项。** 理由：小模型在逐格上下文下更稳（待评测验证，不作为结论）。代价：token 开销更大。

**ADR-016 · 模型分档（cpu-lite / cpu-std / gpu-std / gpu-ref），档位只是 `RunConfig` 预设，不新增代码路径。** 理由：目标用户的普通电脑多数没有 GPU；CPU 的瓶颈是预填充，所以靠"总是先按键预筛选 + 限制每窗口键数 + 小预算"来压缩输入，而不是为 CPU 另写一套流水线。评测按"档位 × 指标"出表。代价：档位取值是初始假设，必须实测校准；CPU 档准确率可能明显低于 GPU 档，由 Verifier 标 `needs_review` 兜底。`RunConfig` 新增三个可选字段（`profile`、`prefilter`、`max_keys_per_window`），默认值不改变原有行为。

**ADR-017 · 模型训练统一在 Colab 上进行，不在本地。** 理由：本地与沙箱没有 GPU；合成数据可由 seed 在 Colab 内重建，避免上传大文件。代价：会话与资源有限，训练脚本必须支持断点续训；GPU 型号与耗时只写实测值；权重不入 git。训练不在 M1 范围内。

**ADR-018 · 依赖许可证的人工批准（2026-11-23，由项目负责人批准）。** ①`certifi`（MPL-2.0，`httpx` 的必需依赖）：仅作为未修改的依赖使用，不影响本仓库的 Apache-2.0；**打包 exe 时必须随附其许可文本**，且不得修改其文件。②`defusedxml`（PSF-2.0，元数据写作 "PSFL"，LICENSE 文件已核对为 PSF License v2）：作为默认依赖，使 openpyxl 在解析不可信 xlsx 时自动启用 XML 攻击防护。③`pypdfium2`（BSD-3-Clause / Apache-2.0，随附 37 份第三方许可文件，其中提到 GPL 的 5 份均为例外条款或构建脚本声明，无任何文件本身是 GPL/LGPL 全文）：打包 exe 时需按其 NOTICE 要求随附全部许可文件；该结论基于抽查，不是法律意见。代价：每新增一个 WARN 级依赖都要重新批准；`check_licenses.py` 对 WARN 仍以退出码 0 通过，批准记录以本条为准。

**ADR-016 修订（2026-11-23）** 原先让 CPU 档 `prefilter="always"` 并限制每窗口键数；对合成短文档检查发现总输入 token 反而约为一次问完的 2.2～3.5 倍（启发式估算，各 5 份文档）。改为 CPU 档默认 `prefilter="auto"`、不限键数，旋钮保留用于消融，等真实模型实测后再决定。

**ADR-019 · 合成文档需要可调长度。** 现有合成文档只有约 190～560 个 token，无法检验长文档分窗、预筛选和 CPU 档的预算策略，也会让评测过于乐观。后续让生成器支持长度缩放（增加无关章节、干扰段落、多个相似条款），并在评测报告中按文档长度分组。代价：生成器更复杂，需要重新校准难度档。
